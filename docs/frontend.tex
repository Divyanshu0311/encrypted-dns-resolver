{\Huge\bfseries DoT Front-end}\par
\vspace{4pt}
{\Large\color{muted} Design and progress}\par
\vspace{6pt}
{\small\color{muted} Owner: Dhruv \quad$\cdot$\quad 28 October 2026}\par
\vspace{14pt}

The front-end is the resolver's front door. It accepts encrypted DNS queries from clients over
DNS-over-TLS (TCP port 853), checks each one, passes valid queries to the middleware, and sends
back the encrypted answers. It also decides which clients and queries get rejected, and how.

\textbf{All 11 features are complete and tested}, including end to end with \texttt{dig +tls}.

A connection stays open after a reply, so one client can send many queries without repeating
the TLS handshake. It may send several without waiting (pipelining); each answer goes out as soon
as it is ready, matched to its query by ID.

\normalfont\textbf{Feature} & \textbf{What it does} & \textbf{Status} \\
\midrule

Policy rejections & Answers REFUSED for queries about blocked domains, read from a file & \done \\
Connection handling & Serves many clients at once, several queries per connection, with timeouts
  and limits & \done \\

Runnable server & \texttt{dns\_server <config-file>}, tested end to end with \texttt{dig +tls} & \done \\

\needspace{18\baselineskip}
\section{What the response codes mean}

Every DNS reply carries a response code. FORMERR, NOTIMP, BADVERS and REFUSED say the problem is
with the query; SERVFAIL says the problem is on the resolver's side, so retrying later can
succeed.

{\renewcommand{\arraystretch}{1.25}
\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{33mm}>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}p{17mm}@{}}
\toprule
\textbf{Code} & \textbf{What it means in this resolver} & \textbf{Retry?} \\
\midrule
\textbf{FORMERR}\newline{\small\color{muted}Format error \textperiodcentered{} code 1} &
  \textbf{The query is broken.} It was readable enough to reply to, but breaks DNS rules: wrong
  section counts, a damaged name or one with characters outside letters, digits, \texttt{-} and
  \texttt{\_}, a bad EDNS record, or extra bytes at the end & No \\
\textbf{NOTIMP}\newline{\small\color{muted}Not implemented \textperiodcentered{} code 4} &
  \textbf{Valid, but unsupported.} An operation other than a standard query, a class other than
  Internet (e.g.\ CHAOS), or a record type outside A, NS, CNAME, SOA, PTR, MX, TXT, AAAA and ANY
  (e.g.\ HTTPS) & No \\
\textbf{BADVERS}\newline{\small\color{muted}Bad EDNS version \textperiodcentered{} code 16} &
  \textbf{Wrong EDNS version.} The client used a version above 0, the only one that exists; the
  reply says ``use version 0'' & \textcolor{good}{Yes}, with v0 \\
\textbf{REFUSED}\newline{\small\color{muted}Refused \textperiodcentered{} code 5} &
  \textbf{Understood, but not allowed.} The domain is on the blocked list, or the client is over
  the middleware's rate limit & No \\
\textbf{SERVFAIL}\newline{\small\color{muted}Server failure \textperiodcentered{} code 2} &
  \textbf{No answer could be produced.} The query was fine, but the middleware was overloaded,
  the upstream servers failed, or the answer couldn't be turned into a valid reply &
  \textcolor{good}{Yes}, later \\
\bottomrule
\end{tabularx}}

\needspace{20\baselineskip}
\section{Abuse blocking}

Each client earns \textbf{strikes} for misbehaving. Too many strikes within a time window and its
address is blocked: every new connection from it is reset before the TLS handshake, and an open
connection is reset at its next query. Blocks expire on their own.

\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X@{}}
\toprule
\textbf{Counts as a strike} & \textbf{Doesn't count} \\
\midrule
Being refused by the rate limiter (\emph{rate-limit strike}) & Asking for a blocked domain \\
A failed TLS handshake: not TLS, or a version we refuse (\emph{protocol strike}) & An unsupported
  query (NOTIMP) or EDNS version (BADVERS) \\
A zero-length message, one with no readable ID, or a reply instead of a query (\emph{protocol
  strike}) & Going quiet until the idle timeout \\
A malformed query, FORMERR (\emph{protocol strike}) & Hanging up mid-handshake, or rejecting our
  certificate with an alert \\
\bottomrule
\end{tabularx}

Protocol strikes have their own, \textbf{higher} limit, because honest clients occasionally fail a
handshake or send something odd. IPv6 clients are counted per /64 network, since one device
usually owns a whole /64. A client reaching us as \texttt{::ffff:1.2.3.4} is the same client as
\texttt{1.2.3.4}.

\needspace{14\baselineskip}
\section{How the encryption works}

\begin{itemize}
  \item \textbf{TLS 1.3 only.} Every TLS 1.3 cipher suite uses an ephemeral key exchange and
        authenticated encryption; older versions are refused.
  \item \textbf{The session key is never sent.} Client and server each compute it from a key
        exchange (ECDHE), so someone watching the network can't obtain it.
  \item \textbf{The server proves its identity} by signing the handshake with its private key.
        The key never leaves the server, and the signature stops anyone impersonating it.
  \item \textbf{Forward secrecy.} A stolen private key would let an attacker impersonate the
        server in future, but not decrypt traffic recorded earlier.
  \item \textbf{Length padding} covers the one thing TLS doesn't hide: message sizes.
  \item \textbf{Key file protection.} The server warns at startup if the private key can be read
        by other users, and \texttt{*.pem} / \texttt{*.key} files are kept out of git.
  \item \textbf{ALPN.} A client offering the \texttt{dot} protocol name gets it confirmed; it
        isn't required.
\end{itemize}

\section{What the front-end uses from the middleware}

The middleware is built by a teammate; the front-end calls three of its functions:

\begin{itemize}
  \item \textbf{\texttt{submit(name, type, client, callback)}} hands over a query. The callback
        runs exactly once with the answer, possibly on another thread; the front-end passes the
        encoded reply back to its own I/O thread.
  \item \textbf{\texttt{is\_blocked(address)}} answers ``is this client blocked right now?'', at
        connect time and before each query.
  \item \textbf{\texttt{report\_abuse(address)}} records a protocol strike.
\end{itemize}

\needspace{14\baselineskip}
\section{Building, running and testing}

Needs Linux, \texttt{g++-14}, CMake and OpenSSL 3 (\texttt{sudo apt install g++-14 libssl-dev}).
On other systems everything except the DoT server itself still builds.

\begin{lstlisting}
cmake --preset local && cmake --build build/local    # build
ctest --test-dir build/local                         # run all tests

# a self-signed certificate for local testing
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes \
        -keyout server.key -out server.pem -days 30 -subj /CN=localhost
chmod 600 server.key

build/local/dns_server my.conf                       # with tls_cert/tls_key set
dig @127.0.0.1 -p 853 +tls example.com               # query it
\end{lstlisting}
